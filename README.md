# 短片场记 · 连续性校验 + 现场拍摄排程 + 镜头清单 + 排程变更审计

面向短片拍摄的场记工具，包含四个相互独立又共享场景数据的模块：

1. **连续性校验**：以**故事时间 + 同刻序号**组织场景（与实际拍摄顺序无关），为角色/道具建立状态字段，录入每个场景开拍前的**期望快照**与结束后的**显式状态变更**；系统自动按故事线**重放**全部变更，逐字段比对「推导状态 vs 期望快照」，标出**首次分歧及其来源场景**，并在任何顺序/快照/变更调整后**自动重算**。
2. **现场拍摄排程**：场景可填写**拍摄地点、预计分钟数、不可提前的故事序号**；系统按**拍摄日期**生成**确定性**排程——在满足故事顺序约束与**锁定场次**的前提下，优先**合并同地点场景、最小化地点切换**，逐日展示每次地点切换（含切换/不合并的原因）与各类冲突；用户可锁定/解锁场次、调整拍摄日期与单日时长后**重新计算**。排程**不会改动**连续性校验的故事时间线。
3. **镜头清单（含前置镜头与可拍队列）**：每个场景维护**镜头编号、景别/机位、是否必拍、备注**，并为每个镜头登记**多次拍摄结果（条）**；编辑镜头时可选择**同场景的多个前置镜头**，服务端保存前检测**自依赖与任意深度环**，拒绝时返回能按镜头编号定位的**闭环路径**，且原关系不会被部分写入。系统按镜头状态（**待拍 / 已拍 / 需重拍**）与**「最佳条」**选择计算**场景完成度**——只有**所有必拍镜头均有可用最佳条**时场景才标记完成；镜头仅在**全部前置镜头都有可用最佳条**时进入**可拍**状态，否则逐项显示阻塞原因（含链式阻塞）；每个场景顶部按**「必拍优先、镜头编号自然序」**生成**下一批可拍镜头**，并支持**只看可拍**。删除镜头时同步清理依赖；最佳条或拍摄结果变化后队列即时重算。列表中突出**缺镜头**与**需重拍**项；支持按场景筛选，保存后即时刷新。镜头清单**不改动**连续性重放，也**不改变**排程逻辑。
4. **排程变更审计**：每次在「现场拍摄排程」**保存拍摄日期/单日容量或锁定/解锁场次并重算**后，服务端自动将本次排程结果与**上一版（或当前基线）按场景逐项比对**，把**新增、移除、日期移动、顺序移动**及**锁定变更、参数调整**落库为一个**版本**，并为每项变更归因（**锁定 / 容量 / 故事前置** / 地点调整 / 场景增删）；**相同输入重复保存不会产生空版本**。审计页可按版本查看**变更摘要、逐场景变更明细与本版排程快照**，并可将任一版本**标记为基线**，后续版本改为与基线继续比较。审计只读取排程结果并写入独立的审计表，**不影响**排程、连续性与镜头清单的任何数据。

技术栈：TypeScript · React (Vite) · Express · SQLite (better-sqlite3)

## 一键启动（Docker）

```bash
docker compose up --build
```

启动完成后，浏览器访问：

- **http://localhost:8080** —— 打开后在顶部选项卡进入「故事时间线」「冲突列表」「现场拍摄排程」「排程变更审计」「场景管理」「镜头清单」「对象与字段」等页面。

健康检查：`http://localhost:8080/api/health`。

- 依赖安装、前端构建、SQLite 建库建表、演示数据写入全部随容器启动自动完成，无需任何手工步骤。
- 数据库文件持久化在命名卷 `continuity-data` 中（容器内路径 `/app/data/continuity.db`）。
- 旧版 Compose 可使用 `docker-compose up --build`。

## 配置项（均为环境变量，均有默认值）

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `8080` | HTTP 服务端口（Compose 已映射 `8080:8080`） |
| `DATABASE_PATH` | 容器内 `/app/data/continuity.db`；本地 `./data/continuity.db` | SQLite 数据库文件路径，启动时自动建目录、建表 |
| `SEED_DEMO` | `1` | 首次启动且库为空时写入演示数据（含两处刻意制造的连续性冲突，多地点、顺序约束、锁定场次的排程示例，覆盖「已拍/待拍/需重拍/缺镜头」与前置阻塞/链式阻塞/可拍队列的镜头清单示例，以及一个排程审计初始版本）；置 `0` 关闭 |

修改端口示例：`docker compose up --build` 前编辑 `docker-compose.yml` 的 `ports`，或本地运行时 `PORT=9000 npm start`。

## 功能与使用流程

### A. 连续性校验

1. **对象与字段**：建立角色/道具，为每个对象定义状态字段（key、显示名、初始值），如「林雪 · 服装 = 蓝色风衣」。
2. **场景管理**：按 `故事时间`（可排序字符串，建议 `D01 21:00` 格式）+ `同刻序号` 录入场景；为每个场景填写：
   - **期望快照**：该场景开拍前，某对象某字段应有的值（留空表示不校验该字段）；
   - **显式状态变更**：该场景结束后生效的状态改写（如「旧怀表 · 表盖 → 打开」）。
3. **故事时间线**：系统从字段初始值出发，按 `(故事时间, 同刻序号)` 重放所有场景：每个场景开拍前逐字段比对推导状态与期望快照，随后应用该场景的显式变更。每条比对都标注推导值的**来源**（初始值或某场景的变更）。
4. **冲突列表**：汇总所有不一致，可按对象筛选、可只看每个「对象+字段」的**首次分歧**，并给出造成该推导值的**来源场景**——修复首次分歧后重算，后续连锁分歧往往随之消除。
5. **自动重算**：校验结果由服务端在每次请求时现算，任何场景顺序、快照、变更、字段的调整保存后立即反映到时间线与冲突列表。

### B. 现场拍摄排程（与故事时间线相互独立）

1. **场景排程信息**（在「场景管理」中填写）：
   - **拍摄地点**：自由文本，同名地点视为同一处（如 `A 棚 · 公寓内景`）；
   - **预计分钟数**：该场的拍摄时长；
   - **不可早于故事 #**：该场只能在故事线第 `1..N` 场**全部拍完之后**拍摄（`0` = 无约束）。故事序号由 `(故事时间, 同刻序号)` 确定性排名，直接展示在场景卡片上。
2. **排程设置**：在「现场拍摄排程」顶部维护**拍摄日期列表**与**每个拍摄日的预计可用分钟数**。
3. **确定性排程规则**：服务端每次请求按固定规则现算（相同输入必得相同结果）：
   - 锁定场次固定为锚点；逐日、逐空位贪心选择；
   - 候选中**优先当前地点的同地点场景**（合并、零切换）；必须切换时选择**现在可连续拍摄同地点场次最多**的地点，以最小化全程切换次数（所有并列均按故事序号/地点名/场景 id 确定地打破）；
   - 若提前拍某场会导致未来必须折返同地点（其同地点伙伴受故事顺序约束、要等更晚拍摄日的锁定场次之后才能拍），当日会提前收工并说明原因。
4. **切换与冲突展示**：逐日列出场次、分钟区间与合并标记；每次**地点切换 / 跨日延续 / 提前收工**都给出文字说明；冲突类型包括：
   - **容量冲突**：某日累计分钟数超出单日预计，或所有拍摄日都装不下（追加到最后一个拍摄日）；
   - **顺序冲突 / 锁定冲突**：自由场次或锁定场次在其前置故事拍完之前拍摄；
   - **锁定重叠 / 锁定失效**：同一拍摄日同一位置锁定了多场，或锁定到已删除的拍摄日期。
5. **锁定 / 解锁 / 重算**：在排程卡片上把任一场次锁定到「某拍摄日的第 N 个拍摄位置」，或解锁；调整日期、单日时长后点击「保存设置并重算」，排程立即按新约束确定性重算。

> 两个模块共享场景但互不干扰：排程只读取故事顺序、地点、时长与锁定信息，**不读取也不修改快照与状态变更**；无论如何排程，「故事时间线」的连续性重放结果都保持不变。

### C. 镜头清单（独立于连续性校验与拍摄排程）

1. **建立镜头**：在「镜头清单」页的场景卡片底部录入**镜头编号**（如 `1`、`2A`）、**景别**（远景/全景/中景/近景/特写…，可自由输入）、**机位**（A 机/手持/轨道…）、**是否必拍**与**备注**；已有镜头可随时修改或删除。
2. **登记拍摄结果**：每个镜头可登记**多条拍摄条**（条号自动递增），每条可标记**可用 / NG**、填写备注，并可将其中一条选为**「最佳条」**（★，每个镜头至多一条，再次点击取消）。
3. **前置镜头**（访问入口：镜头行右侧的「🔗 前置」按钮）：
   - 点击展开**同场景镜头多选框**，勾选必须先拍完（即已有**可用最佳条**）的一个或多个镜头，然后点该行的**保存**；
   - 服务端在保存前统一校验：不能选择自身（**自依赖**）、不能选其他场景的镜头、不允许**任意深度的闭环依赖**；
   - 校验失败时返回 **400** 与可直接定位的闭环路径（如 `镜头 1 → 镜头 5 → 镜头 4 → 镜头 1`，字段 `code` / `cycleShotIds` / `cycleShotNos` / `cyclePath`），前端在顶部错误条显示；由于校验与写入在**同一数据库事务**中，被拒绝时镜头字段与原有前置关系**都不会被部分写入**；
   - 删除镜头时，它作为别人前置的入边与它自己的出边都会**同步清理**（数据库外键级联 + 显式删除双保险）。
4. **可拍状态与逐项阻塞**：镜头仅在**全部前置镜头都有可用最佳条**时标记为 **▶ 可拍**（无前置的镜头天然可拍；与镜头自身是待拍/需重拍无关）。否则显示 **⛔ 被前置阻塞**，并在下方逐项列出原因（如「前置镜头 3 待拍（尚未登记拍摄条）」「前置镜头 4 需重拍（尚无可用最佳条）」）；若某个前置**自身的前置也未就绪**，会额外标注链式阻塞。
5. **下一批可拍镜头与「只看可拍」**：每个场景卡片顶部的 **🎬 下一批可拍** 区域，按**必拍优先（★）、镜头编号自然序**（数字按数值比较，故 `2 < 10`）列出所有前置已就绪且尚未完成的镜头，点击条目可平滑滚动定位到该镜头；顶部筛选区勾选**「只看可拍」**即只显示这些镜头所在的场景。汇总徽标同步显示 **▶ 现在可拍 N**。
6. **即时重算**：拍摄条的新增、可用/NG 切换、最佳条选择/取消、镜头或前置关系的增删，都会触发服务端整体现算并刷新，可拍队列与阻塞原因**立即更新**（例如把某条最佳条改标 NG，所有依赖它的镜头会立刻回到阻塞状态）。
7. **镜头状态**（服务端现算，无需手工维护）：
   - **待拍**：尚未登记任何拍摄条；
   - **已拍**：存在**可用的最佳条**（被选中且未标 NG）；
   - **需重拍**：有条但无可用最佳条——并区分原因：*未选定最佳条 / 最佳条不可用 / 全部条不可用*。
8. **场景完成度**：按「有可用最佳条的镜头 ÷ 总镜头」计算进度条；**只有所有必拍镜头均有可用最佳条时，场景才标记为完成**（未建任何镜头的场景不算完成；前置设置不影响完成度判定）。
9. **突出显示**：场景卡片以边框颜色与徽标突出 **缺镜头**（一个镜头都没建）、**需重拍 N**、**待拍 N**、**可拍 N** 与 **✅ 场景完成**；可拍镜头行有绿色左侧标记、被阻塞镜头行有橙色标记；顶部汇总条与顶栏徽标同步显示整体进度。
10. **筛选与刷新**：可按场景下拉筛选、勾选「只看未完成场景」「只看可拍」；任何保存（镜头/前置/拍摄条/最佳条）都会触发整体刷新，状态、队列与完成度即时更新。

> 镜头清单只读写 `shots` / `takes` / `shot_prereqs` 三表：不读取也不修改快照、状态变更、排程设置与锁定，删除场景时其镜头、拍摄条与前置关系随外键级联清理。

### D. 排程变更审计（只读取排程结果，不改任何业务数据）

1. **自动记录版本**：以下三类「保存并重算」操作完成后，服务端会把本次排程结果与对比基准逐项比对并落库为一个**版本**（与写操作同一事务，任一失败整体回滚）：
   - 「现场拍摄排程」顶部**保存设置并重算**（拍摄日期列表 / 单日预计分钟数）；
   - 任一场次的**锁定**（锁到某拍摄日第 N 位）；
   - 任一场次的**解锁**。
2. **逐项比对与归因**：每个版本相对其对比基准（默认上一版；设置基线后为基线版）按场景记录：
   - **变更类型**：`新增`（场景首次进入排程）、`移除`（场景被删除）、`日期移动`（拍摄日变化）、`顺序移动`（同日内位置变化）、`锁定变更`（仅锁定状态变化）、`参数调整`（位置未变但时长/故事前置/地点/分钟区间等变化）；
   - **变更原因**（可多个）：`锁定`（本场或他场锁定/解锁引起）、`容量`（单日分钟数 / 拍摄日期列表 / 本场预计分钟数 / 超时状态变化）、`故事前置`（「不可早于故事 #N」或故事序号变化）、`地点调整`、`场景增删`、`其他`。
3. **不产生空版本**：版本以排程结果的**指纹**（SHA-256，覆盖落位/锁定/时长/约束等全部排程相关字段）判重——与上一版相同（同一输入重复保存）、或回到了对比基准的状态（如撤销回基线）、或逐项比对后无任何场次变化（如仅改了不影响排布的设置）时，都**不会**写入空版本。
4. **基线**：在审计页可将任一版本**设为基线**（同时至多一个），此后新版本改为与基线比较；可随时**取消基线**恢复与上一版比较。每个版本都记录自己当时的对比基准（`baseVersionNo` + 是否为基线），历史可溯源。
5. **审计页**：左侧**版本列表**（版本号、时间、触发动作、变更数、基线标记），右侧**版本详情**——变更摘要（按类型/原因的计数）、**逐场景变更明细**（含人类可读的移动描述与原因说明）、**本版场次详情**（该版完整排程快照表，本版有变更的场次高亮）；点击「对比基准」可跳转到基准版本。
6. **首个版本**：演示数据首次启动时会自动记录 `V1 初始版本`（只落快照、无变更条目），作为后续保存的比较起点；未播种时，第一次保存设置/锁定也会产生初始版本。

> 审计模块只调用排程引擎的现算结果并写入 `schedule_audit_versions` / `schedule_audit_changes` / `schedule_audit_meta` 三张独立表：不读取也不修改快照、状态变更、镜头数据，也不会反过来影响排程结果。

## API 摘要

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET/POST | `/api/entities` | 对象列表 / 新建（含字段） |
| PUT/DELETE | `/api/entities/:id` | 更新（字段增删改，key 变更自动迁移历史数据）/ 删除 |
| GET/POST | `/api/scenes` | 场景列表（按故事时间排序，含地点/预计分钟/不可早于序号/故事序号）/ 新建 |
| PUT/DELETE | `/api/scenes/:id` | 更新（含故事时间、同刻序号、地点、预计分钟数、不可早于故事序号）/ 删除 |
| PUT | `/api/scenes/:id/snapshot` | 整体替换该场景的期望快照 |
| PUT | `/api/scenes/:id/changes` | 整体替换该场景的显式变更 |
| GET | `/api/continuity?entityId=` | 重放并返回时间线比对结果与冲突列表（可按对象过滤） |
| GET | `/api/schedule` | 按拍摄日返回确定性排程、切换/收工事件与冲突原因 |
| GET/PUT | `/api/schedule/settings` | 读取 / 更新拍摄日期列表与单日预计分钟数（PUT 保存重算后自动记录审计版本） |
| PUT | `/api/schedule/:id/lock` | 锁定场次到 `{date, ordinal}`（位置冲突返回 409），返回最新排程（同事务记录审计版本） |
| DELETE | `/api/schedule/:id/lock` | 解锁场次，返回最新排程（同事务记录审计版本） |
| GET | `/api/schedule/audit` | 审计版本列表（新→旧，含触发动作、变更数、按类型/原因的摘要）与当前基线 |
| GET | `/api/schedule/audit/:id` | 单个版本详情：变更摘要、逐场景变更（类型 + 原因 + 说明）与本版排程快照 |
| PUT | `/api/schedule/audit/baseline` | 设置/清除基线（`{versionId}`，`null`/`0` = 清除）；后续版本与基线比较 |
| GET | `/api/shots?sceneId=` | 镜头清单：各场景镜头（含状态/最佳条/前置/可拍状态与逐项阻塞原因）、场景完成度、**下一批可拍队列**与汇总，可按场景过滤 |
| POST | `/api/scenes/:id/shots` | 新建镜头（编号/景别/机位/必拍/备注，可选 `prerequisiteShotIds` 同场景前置），返回最新清单 |
| PUT/DELETE | `/api/shots/:id` | 更新 / 删除镜头（更新可选 `prerequisiteShotIds`：自依赖/跨场景/任意深度环返回 400 及 `code`、`cyclePath` 等定位信息且整事务回滚；删除级联清理拍摄条与前置关系），返回最新清单 |
| POST | `/api/shots/:id/takes` | 登记一条拍摄结果（条号自动递增），返回最新清单 |
| PUT/DELETE | `/api/takes/:id` | 更新（可用/NG、备注）/ 删除拍摄条，返回最新清单 |
| PUT | `/api/shots/:id/best` | 选定/取消「最佳条」（`{takeId}`，`0` = 取消；每镜头至多一条），返回最新清单 |
